## 0. 兩種重心

| | 記錄 | 回顧 |
|---|---|---|
| 情境 | 剛走出影廳，站在商場走道 | 晚上，坐著 |

斷點：`sm 640` / `md 768` / `lg 1024` / `xl 1280`。設計基準 375px 與 1280px 兩點，中間線性。

### 2.1 年表 YearStrip — 全站簽名

每年一列，一列 53 格（**每格是一週，不是一天**）。

**為什麼是週而不是日**：實測 169 筆分散在 12 年，日層級的填滿率約 6%——一張 7×53 的年格子有 96% 是空的，看起來不是「密度」而是「荒涼」。收成週之後填滿率跳到約 22%，2016–2020 的密集期與 2021–2022 的空窗立刻讀得出來。這是真實資料逼出來的偏離，不是懶。

- 純 SVG／CSS grid，**不需要圖表庫**（舊專案用 d3 手寫 imperative DOM，在 SSR 下是負擔）
- 格子 8×8px、間距 2px（節距 10）→ 一列 530px。手機上縮到 5×5px（節距 7）→ 371px，**剛好塞得進 375px，不需要橫向捲動**
- 色階：0 場 → `heat-0`；1 場 → `heat-2`；2 場 → `heat-4`；3 場以上 → `heat-6`
- 右側對齊該年總場次，Inter `tabular-nums`
- **它同時是年份選擇器。** 點某一列 → 該年成為 active（`▸` 標記 + 琥珀左邊框），下方列表與統計跟著換。這解決了「年份下拉選單會讓人選到只有 2 筆的 2015 年」的問題——你在選之前就看得到那年有多少東西。
- 鍵盤：`↑↓` 換年、`Enter` 選定；每列有 `aria-label="2019 年 25 場"`

### 2.2 兩種檢視

`[ 條列 | 網格 ]` 切換，預設**條列**（票根卡）。

網格是 2:3 磚塊：有海報的是海報，沒海報的是票根磚。切換狀態存 `localStorage`。

Simkl 的做法佐證這個方向：官方提供 Table / Poster / Card 三種版面且可「Hide Poster Image」。**海報供給不均時，把密度交給使用者，不要替他決定。**

### 2.3 手機

- 年表縮到 5px 節距，`overflow-x` 不需要
- 票根卡的海報欄縮到 48px 寬，或在 `<640px` 直接不顯示（票根卡本來就完整）
- 月份標題 sticky

## 3. `/u/[username]/[year]` 年度回顧（SSR，不快取）

⚠️ **這是全站首屏成本最高的一頁**：`routeRules` 給 `/u/**` 的是 `cache-control: private, no-store`（RLS 依觀看者而異，絕不可快取），而圖表 100% 在 client 端算。骨架必須做好。

Letterboxd 的 Year in Review 是編輯式長捲頁而不是 dashboard（14 個具名章節、每節整版換底色、委製插畫）。**年度回顧與日常 App 是兩個不同的設計語域，這是可以放大的許可證。**

章節（每節整版，垂直捲動）：

1. **這一年** — 年份數字設到 72px，年表該列放大
2. **去了幾次** — 年度出席圖（7×53 日格）
3. **什麼時候看** — 時段熱點圖 + 一句話結論（「你 71% 的場次在週五到週日的晚上」）
4. **在哪裡看** — 影城分布橫條 + 主場那一句
5. **看了什麼** — 國別、版本分布；多刷排行
6. **花了多少** — **只有 `show_cost` 為真時才存在整個章節**（見 §12）

稀疏年份的降級：2015 年只有 2 筆。此時不畫出席圖（一張 3 格有色、362 格空的圖沒有意義），改成直接列出那 2 筆票根卡，標題寫「2015 年你看了 2 場」。**章節數量隨資料量伸縮，不留空圖。**

## 4. `/u/[username]/records/[id]` 單筆分享頁（SSR，不快取，US-32）

一張票根，放大。這頁存在的理由是分享。

**OG 圖**（1200×630）就是那張票根：

```
┌────────────────────────────────────────────┐
│                                            │
│   2026 / 07 / 26 (六) 16:00                │
│                                            │
│   劇場版 吉伊卡哇                          │
│   人魚島的秘密                              │
│                                            │
│   林口威秀 (7廳)　2D　2張                   │
│                                            │
│   clipwww ・ 影記                           │
└────────────────────────────────────────────┘
```

三個實作約束（設計必須先知道）：

1. **OG 圖裡的中文需要字型 buffer，不是 CSS font stack。** §2 決定了中文走平台系統字型——但 OG 圖是伺服器端算圖，伺服器上沒有蘋方。**OG 圖必須自帶一份中文字型檔**（可以子集化，因為片名字彙來自我們自己的片庫）。這是全站唯一需要中文字型檔的地方。
2. **爬蟲是 anon 身分**，所以 OG 圖**永遠不畫票價**，不論 `show_cost`。
3. 無海報的作品，OG 圖就是純票根版面——**不要放灰色佔位圖**。

### 5.1 核准紀錄要能收合

實測最極端的案例是《TAYLOR SWIFT | THE ERAS TOUR》，**一部片有 13 張證明書**。核准紀錄區預設顯示 1 筆（最新），`> 還有 12 筆核准紀錄` 收合。

`certificate` 的 `permit_no` 在 110–112 年跨系列撞號（110 年 128 筆、111 年 143 筆、112 年 157 筆重複）——**UI 上不要把字號當成識別碼呈現**（不要做成可複製的 ID、不要當標題），它只是屬性。

### 5.2 無 TMDB 的 268 部

這 268 部只有政府核准資料：中文片名、國別、片長、級別、年度。**這個版面對它們完全成立**——沒有海報欄，核准紀錄照樣是英雄。不會出現「資料不完整」的觀感，因為版面本來就不是為海報設計的。

### 5.3 ISR 安全

⚠️ 「我看過這部片幾次」這類個人化內容**一律 client 端補**。SSR 期間碰使用者身分會讓第一個造訪者的 RLS 結果被快取給所有人。

⚠️ ISR 路由會額外產生 `_payload.json`。票價**必須在 RLS 層擋掉**，不能只靠 `v-if` 隱藏——HTML 沒顯示，payload 也會被快取並公開可讀。

## 6. `/venue/[id]` 影城頁（SSR + ISR 3600）

影城名、公司名、地址、電話、廳數、地圖點位；誰在這裡看過什麼。

⚠️ **111 筆裡有 3 筆 `name` 是空字串**（統編 54186685、21235165、25116865），只有 `companyName`。所有影城名稱一律用 `displayName = name || companyName`。空字串不是缺漏，是政府 CSV 的常態。

### 8.1 「找不到這部片」是一等公民

硬約束 (1) 的具體實作。實測：David 的 169 筆紀錄有 **56.8% 對不上現有片庫**（以不重複片名計是 **61.9%**，134 個片名裡 83 個沒命中）。搜尋落空是常態。

**「＋ 找不到？自己新增這部片」從輸入框取得焦點的那一刻就在列表底部，有結果時也不消失。**

⚠️ **實作上必須用合成 group，不能用 `#footer` 插槽。** `UCommandPalette` 的 `#footer` 只要有帶插槽就恆定渲染（`v-if="!!slots.footer"`），看起來剛好——但 **footer 的內容不在 Listbox 的鍵盤導覽序列中**。「一等公民」意味著按 `↓` 走到最後一項就是它。所以要做成一個 `{ ignoreFilter: true }` 的單項 group 排在最後。

點它 → `/app/films/new`，把已輸入的字帶過去當預填片名。

### 8.3 影城選單

111 筆，依縣市分組（台北市 30、新北市 13、台中市 13、高雄市 10…）。

- `USelectMenu`，巢狀陣列分組 + `{ type: 'label' }` 群組標題
- **最上方固定一組「最近用過」**（不分縣市），這是 68% 命中率的來源
- 非影城的 4 個選項（串流平台／影展／家中／其他）獨立成一組放最下面

### 8.4 收合區

`▸ 票價、票數、影廳、版本` — `UCollapsible`。展開後：

- 票價 `UInputNumber`，前綴 `NT$`
- 票數 `UInputNumber`，預設 1
- 影廳 — 該影城的廳數已知（`hallCount`，總計 932），做成 1..N 的選單
- 版本 — **自由文字 + 建議選項**。⚠️ 實測 David 的 version 值有 `MAPPA`、`4DX 極爆`、`2D (ATMOS)`、`TITAN`、`IMAX 3D`、`4DX 3D` 等 10 種，**這是自由文字欄位，不是 enum**。做成 enum 會逼使用者說謊。建議選項給 2D / IMAX / 4DX / 3D / Dolby Cinema，但可自行輸入。
- 備註 — 實測真實內容是同行者縮寫（`東`、`爸`、`東、宗`）、里程碑（`林口威秀第100場🎉`）、次數（`第 12 次上映`）、場次型態（`4DX連映馬拉松場(下)`）。**含 emoji 與罕用字**，這是 §2.1 決定不做字型子集的直接原因。

### 8.5 送出

1. 按「記下來」→ 按鈕進 loading
2. 成功 → 導回 `/app/records`，新列以 180ms 由上而下 reveal「印」進帳本（DS §6）
3. toast：**「記好了」**
4. 失敗 → 錯誤顯示在按鈕上方，**表單內容完整保留**。⚠️ 30 秒流程失敗時那 30 秒的資料必須存在 `sessionStorage`，重新整理不能弄丟。

同一份表單，`max-width: 560px` 置中（DS §2.4 的中文行長）。不做成兩欄——欄位太少，兩欄只會讓眼睛多跑一趟。

### 9.1 時段軸的兩個真實決定

舊專案最有價值的互動語彙，原樣保留：點出席圖的一格或熱點圖的一格 → `UDrawer direction="bottom"`，高度 90%，標題 `2024/03/15 (週五)` 或 `週三 14:00~15:00`，內容是該時段的票根卡清單。

### 9.3 全新帳號（0 筆）

```

## 12. `/app/settings` 票價隱私（SPA，US-29/30）

**硬約束 (2)。這一頁是全站最需要小心的地方。**

`show_cost` 是一個**全域、預設 false、一翻就追溯套用全部歷史**的布林。翻開它，David 過去 169 筆紀錄的票價、共 NT$5x,xxx 的消費，全部變成公開。

**所以它不能是設定清單裡的一個 `USwitch`。**

```
┌──────────────────────────────────────────────────┐
│  票價                                            │
│                                                  │
│  你的票價現在只有你看得到。                       │
│                                                  │
│  公開之後，任何人打開 /u/clipwww 都會看到你       │
│  169 筆紀錄的每一筆票價，以及年度總花費。         │
│  這會套用到你過去所有的紀錄，不只是之後新增的。   │
│                                                  │
│  ┌────────────────────────────────────────────┐ │
│  │ 別人會看到的樣子                            │ │
│  │ ┌────┬──────────────────────────────────┐  │ │
│  │ │ 26 │ 劇場版 吉伊卡哇 人魚島的秘密       │  │ │
│  │ │ 六 │ 林口威秀 2D 16:00 2張 NT$520      │  │ │
│  │ └────┴──────────────────────────────────┘  │ │
│  │        2026 年花了 NT$3,120                 │ │
│  └────────────────────────────────────────────┘ │
│                                                  │
│              [ 公開票價 ]                        │
│                                                  │
│  隨時可以關掉。關掉之後別人就看不到了。           │
└──────────────────────────────────────────────────┘
```

四條規則：

1. **記錄 ≠ 公開。** 表單永遠可以填票價，這個開關只管**發佈**。要在文案上講清楚，否則使用者會以為關著就不能記帳。
2. **翻之前必須看到後果。** 上面那個預覽區用**使用者自己的真實紀錄**渲染，不是示意圖。
3. **⚠️ 彙總圖必須跟著消失。** `show_cost` 為 false 時，公開頁上「年度總花費」「平均票價」這類彙總**整個章節不存在**——不是畫成 0、不是打馬賽克。否則 `總花費 ÷ 場次` 就能反推個別票價，隱私是假的。自己的 `/app` 儀表板永遠看得到。
4. **隱藏時不留佔位。** 票價是 meta 行最後一項，被擋掉時那一行就是短一截。**絕不渲染 `NT$ ———`**——那等於公告「這裡有一個價格」，反而洩漏了「這個人有記帳」。

### 12.1 NT$0 不等於隱藏

實測 169 筆裡 **16 筆 `cost` 為 0**（兌點票、免費場）。它們必須跟「已隱藏」在視覺上完全不同：

- `cost = 0` → 顯示「**免費**」（或依 memo 顯示「兌換」）
- `cost` 被 RLS 擋掉 → 該欄**不存在**
- `cost` 為 NULL（沒填） → 該欄**不存在**

後兩者長得一樣是可以接受的，因為外人本來就不該分辨得出「沒填」與「不給看」。

### 12.2 這一頁的其他項目

username 改名（US-24，改名後舊網址 301）、匯出（US-46）、刪除帳號（US-47，`UModal` + 打字確認）。**票價區塊獨立在最上方，跟其他項目之間有明顯的視覺分隔**——它不該混在一排開關裡。

## 13. `/app/import` 匯入對帳（SPA，US-56~58）

**產品最大的一次批次決策介面，而且實測資料非常糟：**

| 問題 | 實測 |
|---|---|
| 片名沒對到片庫 | 96/169（56.8%） |
| 影城口語簡稱對官方全名 | **0% 直接命中** |
| 模糊比對會綁錯 | 「林口威秀」→「樹林秀泰影城」 |
| 不在 111 筆名單內 | 1 筆（`イオンシネマ シアタス心斎橋`，日本影城） |

「林口威秀」在 `venues.json` 裡的官方名稱是 `林口MITSUI OUTLET PARK威秀影城`。**沒有任何字串比對演算法能自動搞定這件事，而且錯配比不配更糟。**

│                                                          │
│  林口威秀   115 筆   → [ 林口MITSUI OUTLET PARK威秀影城 ▾]│
│  信義威秀    14 筆   → [ 選擇…                        ▾]│
│  京站威秀    10 筆   → [ 選擇…                        ▾]│
│  大直美麗華   8 筆   → [ 選擇…                        ▾]│
│  イオンシネマ 1 筆   → [ 其他（非台灣影城）           ▾]│
│  ...                                                     │
│                                        [ 下一步 ]        │
└──────────────────────────────────────────────────────────┘
```

**只有 15 個相異影城名稱要對，一次對完覆蓋 169 筆。** 這是整個匯入流程投資報酬率最高的一步，所以放第一步。下拉預設**不預選**任何值——寧可讓人選，也不要靜默綁錯。

第 2 步是片名，96 筆未命中。同樣依相異片名分組（83 個），每個給三個選擇：**選片庫既有的**／**新增為作品**／**先跳過**。

⚠️ **「影城人工對照」這個能力在 `BUILD_PLAN §3` 的路由表上沒有位置。** 它不只匯入時需要——使用者手打的簡稱以後也會需要。建議獨立成 `/app/settings/venues` 或收在匯入流程內並持久化對照表。**這需要 w4:p4 決定。**

## 15. 錯誤與降級態

| 狀態 | 設計 |
|---|---|
| 改名後的舊網址 | Nitro middleware 301，**使用者看不到中間頁**。但若舊名已被回收，落到 404 要說「這個名稱的主人改名了」而不是「找不到頁面」 |
| 被下架的紀錄（`moderation_state`） | 票根卡保留位置，內容替換成「這筆紀錄因著作權通知已移除」+ 申訴連結。**不要整筆消失**——那會讓作者以為資料掉了 |

| 圖表載入失敗 | 顯示資料表 fallback，不顯示破圖 |
| 離線／送出失敗 | 表單內容留在 `sessionStorage` |
