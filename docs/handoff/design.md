## 1. 這一棒發生的最大一件事：調性換了

David 拍板把整體調性從前一棒的「冷結構 + 暖火花」改成**「更重的溫暖收藏感」**
（那正是前一棒交接筆記 §3 標記為「David 當時還沒拍板」的第三個選項）。

**整套色票重算，`DESIGN_SYSTEM §1` 是唯一真值。** 三個具體位移：

1. **中性軸從「幾乎沒有顏色的暖白」變成「看得出來是紙」**——亮底 chroma 0.004 → 0.025（6 倍）。
2. **頁面底與卡片面互換角色**：頁面 = 冊頁台紙（`paper-50` / `950`，較深），
   卡片 = 票根紙（`paper-25` / `900`，較亮）。票根實際地「貼」在冊頁上，深度靠兩層紙不靠陰影。
3. **琥珀從「單一火花」放寬到可以承載表面**。

**被取代的規則**：舊的「一個視圖只用一次重點色」作廢。
**取代它的**：**琥珀可以塗介面，永遠不可以塗資料。**
當初真正在保護的是「顏色不編碼資料」，不是「顏色只准出現一次」。
節制改由 chroma 紀律執行：中性軸 ≤0.031、琥珀表面 ≥0.062，中間沒有東西。

### 沒有跟著改的硬約束（別以為換調性就能一起改）

序列色階仍是單色相明度階、圓角仍 ≤4px、中性軸仍遠離 hue≈210、
不用漸層／發光／按鈕後綴「→」、中文仍不用 webfont、`tabular-nums` 仍由 Inter 供應、
主要物件仍是票根不是海報。

## 2. Nuxt UI 的六個破口（`DESIGN_SYSTEM §1.6`）

前一棒找到三個硬寫死 `#fff`，我又找到三個。**每一個都是「畫面上只是看起來有點淡，
不會有任何錯誤訊息」那一類。**

| # | token | 症狀 |
|---|---|---|
| 1–3 | 亮 `--ui-bg`、亮 `--ui-text-inverted`、暗 `--ui-text-highlighted` | 前一棒已記載 |
| 4 | 暗 `--ui-bg-inverted` = `#fff` | **`UCalendar` 選取日、`UButton neutral solid`、`UTabs`、`UTimeline`、`UStepper`、`UPageCard`** 在暗色是純白。`UInputDate` 內部就是 `UCalendar`，這條踩在新增紀錄主流程上 |
| 5 | 暗 `--ui-border-inverted` = `#fff` | `UCheckbox` / `URadioGroup` 邊框、`UInputMenu` / `UTextarea` 的 ring |
| 6 | 亮 `--ui-primary` **派生自 500 不是 600** | 琥珀文字 **3.16:1**、實心鈕 **3.27:1**，兩個都不及格 |

**第 6 個最值得記住**：`dist/runtime/plugins/colors.js:16` 寫的是
`--ui-primary: var(--ui-color-primary-500)`（亮）／`400`（暗）。
本文所有亮色琥珀對比都是以 **600** 算的，不覆寫就全部不成立。

還有第七個不是 token 是尺寸：**`--ui-radius` 預設 `0.25rem`**，
而 Nuxt UI 主題實際用 `rounded-md`（59 處）與 `rounded-lg`（26 處），
也就是預設狀態下全站是 6px / 8px 圓角，直接違反「圓角 ≤4px」。

### ⚠️ 通則（我自己漏了才寫下來的）

> **凡是在未分層 `:root` 覆寫的 token，都必須在 `.dark` 給一個對應值。**

`:root` 在暗色模式一樣命中 `<html>`，而 Nuxt UI 的 `.dark` 在 `@layer theme` 裡，
未分層的 `:root` 會**贏過**它——所以你在亮色寫的值會**漏進暗色**。
我的交付稿第一版就漏了 `--ui-text-inverted`，後果是暗色的主要行動按鈕只有 **2.23:1**。
是 frontend 落地時實測抓到的，不是我自己發現的。

## 3. 我做錯又修掉的（這一節比任何一條做對的規格值錢）

### 3.1 `--week-start` 做成 CSS 變數，但沒有任何 CSS 讀得到它

我裁定週起始日改週一，並沿用前一棒的 `--week-start` token。
**但真正的消費者全部在 TS 端**：ECharts 的 `calendar.dayLabel.firstDay`、
熱點圖軸順序、年表週分桶。`UCalendar` 也不吃 CSS 變數。
換句話說 `main.css` 那一行**不會讓任何東西真的改變行為**。

真值現在放在 TS 常數（`DESIGN_SYSTEM §5.4`），CSS 那一行降級成文件用途。
**教訓**：訂 token 之前先問「誰會讀它」，不要因為別的 token 都在 CSS 就把它也放進去。

### 3.2 「影城不可切開」我寫成了 `nowrap`

`DS §4.3` 我要求影城名是不可切開的單位。實作照做，結果 `/app/records` 在 375px 下
變成 `林口MITSUI OUTLET PARK威...`——**省略號直接毀掉產品的第二個價值主張**
（「記得住你在哪看的」），而且那是 David 68% 場次的主場，八張卡有五張都這樣。

我原本的意思是「它與其他量詞之間不可斷」，寫成 `nowrap` 是過度規定。
改成優先序：**不 truncate ＞ 不與其他量詞混 ＞ 不換行**。
**教訓**：寫約束時要寫「要保住什麼」，不要直接寫成一個 CSS 屬性——
實作會照字面做，而字面通常比意圖窄。

### 3.3 改了 `--ui-radius` 卻沒把 class 映射寫下來

我把 `--ui-radius` 設成 `0.125rem` 之後，`rounded-sm` 不再是 4px 而是 2px。
`§3` 只寫了「`--radius-card: 4px`」，沒說對應哪個 class，
於是 band 卡用了 `rounded-sm`（2px）——在「≤4px」之內所以沒壞，但用了 chip 的語彙。
`§3` 現在有一張 class 映射表。

### 3.4 前一棒也犯過、規則寫了但沒套用到全部地方

前一棒記載「色階少於 7 階時要拉開取值」（相鄰階在暗色只有 1.64:1）。
那條規則寫進了 `DESIGN_SYSTEM`，**但 `SCREENS §2.1` 的年表色階仍然是 `heat-0/2/4/6`**，
關鍵區分只有 1.84:1，而且第四階（3 場以上的週）**永遠不會被畫出來**
——實數是 689 個週格中 537/135/17/**0**。
mockup 是對的，規格文字沒跟上。**規則寫在一處，要自己去查它在別處有沒有被違反。**

## 4. 我結掉的兩題（前一棒標為「還沒有答案」）

### 4.1 OG 圖的中文字型 — 那個「衝突」不成立

前一棒的推導：OG 圖需要字型檔 → 與「中文不用 webfont」衝突 → 只能子集化 →
子集化會讓 UGC 破字 → 無解。

**斷點在第二步。** `§2.1` 管的是**送到瀏覽器的位元組**；
OG 圖的字型待在 serverless function 裡，永遠不會送到任何人的瀏覽器。
再拆一層：**破字是「子集化」造成的，不是「用字型檔」造成的**，
而子集化存在的唯一理由就是省客戶端位元組——伺服器端沒有這個理由。

> **答案：打包完整的 Noto Sans TC，不做子集。**

**方法比結論重要**（下一個字型問題還會用到）：我實際下載字型（7,090,820 bytes = 6.76 MB）、
手寫 cmap parser 解析出 20,745 個碼位、逐字比對 `.data` 的 2,669 部片名與 108 家影城名。
結果推翻了前一棒憑印象列的缺字清單：

| 前一棒列的 | 實測 |
|---|---|
| `猗窩座`、`儸`、`殞` | **全部都在字型裡** |
| `🎉`、`斎` | 真的缺 |

那份 30 字清單是對「**子集**」講的，套到完整字型上不成立。
**這就是這題看起來無解的原因：前提被沿用了，但前提已經換了。**

實測缺字率：中文片名 **5/2669（0.2%）**、影城名 **0/108**、使用者名稱 **0**（DB 約束純 ASCII）、
**原文片名 344/2669（12.9%）→ 所以不放上 OG 圖**。完整推導在 `DESIGN_SYSTEM §2.7`。

⚠️ **硬約束：OG 路由必須跑 Node runtime。** Vercel Edge 是 1MB（Hobby）/ 4MB（Pro），
放不下 6.76MB 的字型。

⚠️ **emfont 順帶結案**：實際 curl 過，`font.emtech.cc` 回 200 服務還在，
但它是**客戶端** webfont 服務，對 OG 圖沒有用——伺服器端算圖要的是一個檔案不是 CDN。
跟這題無關，別再為了這題去查它。

### 4.2 週起始日 → 週一（`--week-start: 1`）

理由：這兩張圖是**回顧物不是日曆**（沒人在上面挑日期），週日起始會把
「週五六日晚間是熱區」這個最強的洞察拆到色帶兩端；週一起始同時讓年表分桶等於 ISO 8601 週。
代價（列標籤第一格變「一」，與台灣實體月曆不同）寫在 `DESIGN_SYSTEM §5.4`。

## 5. 圖表：兩個新的沉默失敗

### 5.1 `visualMap.pieces` 用 `min`/`max` 會漏掉邊界值

寫 `{min:6,max:7}` 接 `{min:8}`，**值剛好等於 8 的那一格靜默不畫**，
露出底紙看起來像渲染破洞；**值 9 反而正常**。
ECharts 把 pieces 當連續區間處理，`(7, 8)` 這段沒人認領，邊界值掉進縫裡。

**一律用 `gt` / `lte`。** 出席圖的 `{min:1,max:1}` 接 `{min:2}` 有同樣的問題，
會讓「剛好 2 場」的 4 天消失——**而那 4 天正是雙片連映，是那張圖唯一想讓人看見的東西**。

發現方法值得記：我逐像素掃 7×16=112 格，跟 `<details>` 的資料表對帳，才定位到是哪一格。
然後用 `git show` 拉出改動前的版本重跑，**確認那是繼承來的而不是我改壞的**。

### 5.2 `baseTooltip` 的顏色一直是 undefined

`T().text` 這個 key 在 PALETTE 裡根本不存在（只有 `text0..text3`），
所以文字色一路吃 ECharts 預設。**tooltip 要 hover 才看得到，截圖驗證抓不到。**
驗法：`dispatchAction({type:'showTip'})` 強制渲染，再從 DOM 讀回 inline style。
